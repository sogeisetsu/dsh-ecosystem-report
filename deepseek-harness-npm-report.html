结论摘要

  1. 生态高度集中。422 个包中，308 个由 @deepseek-ai/dsh 及其 bundle 的依赖闭包一次性带入，用户无需逐个安装。
  2. 落盘不等于启用。308 个已落盘包中只有 205 个默认加载，103 个处于"在磁盘上但未加载"状态。
  3. 未加载分三种原因。官方可选 bundle（15 个，开关即用）、库与内部件（75 个，由使用方加载）、仅其他预设或入口声明（13 个）。
  4. 不在闭包内的 114 个包用途有限。其中 2 个为官方按需包，1 个为官方可选但未随包，其余 110 个无官方入口。
  5. 两个易误判点：Office Skill（dsh-skill-office）与 MCP 客户端（dsh-mcp-client）都随包落盘，但 Web 入口默认不加载：前者只在 sdk 入口的插件行里启用，后者需在插件页或配置中挂载。
  6. 外部清单要逐个核对。第三方整理的 19 项社区增强清单里，5 项在 npm 查不到（只在 GitHub）、1 项已废弃、1 项是官方随包件（不属社区，未列入社区表），剩下 12 项能按包名安装（其中 2 项要先写对实际包名）。合并后的清单见「社区与推荐 → 社区包精选」。

复用的是模板

新建 desktop profile 时按 Web 模板生成 bundle 列表（dsh-base + dsh-web-app），此后两者可各自增删只属于自己的插件。

状态完全独立

可执行包、插件激活、lockfile 与 node_modules 互不共享。web profile 里装的插件，在 desktop profile 里看不到，反之亦然。

给 desktop 装插件：先启动一次桌面端完成 profile 初始化，退出后执行 dsh plugin --profile desktop add <包名>，再打开桌面端生效。桌面端另带 Office Skill 运行时（runtime/office-skills）。

依据：apps/desktop/README.md 的状态归属表 —— CLI 与 Desktop 共享 $DSH_HOME 下的产品数据，但「never executable packages, plugin activation, lockfiles, or node_modules」。

安装建议

按当前状态与能力缺口分层，官方包与社区包分列。

建议的形成方式

排序依据三项：当前状态成本（已加载的最省事）、能力缺口（官方尚未覆盖的部分）、维护风险（官方包有兼容承诺，社区包没有）。

按状态编号，可执行动作只有四类：
· 1a / 1b / 1c → 已在加载，无需操作；
· 2a → 插件页开启，包已在磁盘，不会重新下载；
· 2c → 切换到对应预设（minimal / cordis）或入口（sdk / headless / acp）；
· 3a / 3b → 插件页「发现 / 更多」安装；社区包 → 插件页安装或 npm i。
· 2b / 3c → 不构成安装选项：2b 由使用方自动加载，3c 装了也不会被加载。

执行顺序

  1. 最小可用：npx @deepseek-ai/dsh web → 填写 DeepSeek API Key → 选择工作区。
  2. 长期使用：开启 terminal-bundle、session-search、session-titles；接受自动评审再加 auto-review。
  3. 文档处理：开启 dsh-skill-office（已落盘，默认未启用）。
  4. 外部工具接入：配置 dsh-mcp-client，挂载 MCP 服务端。
  5. 跨 Agent 协作：安装 dsh-subagent-claude-code 或 dsh-subagent-codex（官方按需包）。
